## ۱. خلاصهٔ دسترسی

| منبع | میزبان | وضعیت شبکه | ساختار داده | نقش در MVP |
|---|---|---|---|---|
| Eventro | `eventro.ir` | ✅ HTTP 200 | **ساختاریافته** | **منبع اصلی** |
| Exhibition Makers | `exhibitionmakers.com` | ✅ HTTP 200 | ضعیف | تکمیلی |
| Kabir Karsan | `kabirkarsan.com` | ✅ HTTP 200 | ضعیف | تکمیلی |

| Shahr-e Aftab | `shahreaftab.*` | ❌ بدون رکورد DNS | — | حذف |

### مسئلهٔ مسدودی دوطرفه

`iranfair.com` و `calendar.iranfair.com` به `62.60.210.74` **درست resolve می‌شوند** اما اتصال TCP کاملاً timeout می‌خورد. یعنی فیلترینگ در سطح شبکه است — نه مشکل DNS، نه TLS، نه User-Agent. تغییر هدر یا retry آن را حل نمی‌کند.

در جهت معکوس، بسیاری از سایت‌ها و CDNهای بین‌المللی IPهای ایران را به‌دلیل تحریم مسدود می‌کنند.

**نتیجهٔ معماری:** هیچ میزبان واحدی نمی‌تواند همهٔ منابع را بخواند. راه‌حل بلندمدت، الگوی Relay است (ARCHITECTURE.md). تا آن زمان، Adapterهای منابع مسدود نوشته می‌شوند اما با `enabled = false` می‌مانند.

## ۲. Eventro — منبع اصلی

**چرا بهترین است:** تنها منبعی که هر چهار چیز موردنیاز ما را ساختاریافته می‌دهد.

### الگوی URL

```
https://eventro.ir/tc/fairs/{location}
```

`location` هم شهر ایرانی است و هم کشور خارجی — **دقیقاً همان قالب**:

```
/tc/fairs/tehran     /tc/fairs/germany    /tc/fairs/turkey
/tc/fairs/dubai      /tc/fairs/china      /tc/fairs/france
```

یعنی **یک Adapter واحد هم فاز ۱ (تهران) و هم فاز ۳ (بین‌المللی) را پوشش می‌دهد.**

### فیلدهای هر رکورد

نمونهٔ واقعی استخراج‌شده:

```
نمایشگاه بین المللی الکترونیک، کامپیوتر و تجارت الکترونیکی (الکامپ) تهران 1405
کد رویداد:      53066
وضعیت:          8 روز تا برگزاری
تاریخ برگزاری:  09 شهریور 1405
                31 August 2026
مکان:           تهران
```

| فیلد سایت | نگاشت به مدل ما | اهمیت |
|---|---|---|
| `کد رویداد` | `sourceExternalId` | **شناسهٔ پایدار** → کلید Dedup و Change Detection |
| `تاریخ برگزاری` (میلادی) | `startDate` | **مستقیم استفاده شود** |
| `تاریخ برگزاری` (شمسی) | فقط برای اعتبارسنجی متقابل | — |
| `مکان` | `venue` / `city` خام | نیاز به نگاشت |
| `وضعیت` | `status` | «برگزار شده» / «N روز تا برگزاری» |

### قانون طلایی تاریخ

صفحه **هر دو تقویم را کنار هم** می‌دهد. پس:

> **هرگز خودمان شمسی را به میلادی تبدیل نکنیم.** تاریخ میلادیِ خودِ صفحه را برداریم و تاریخ شمسی را فقط برای تأیید متقابل استفاده کنیم. اگر این دو با هم نخواندند، رکورد به صف بازبینی برود.

این کار یک کلاس کامل از باگ‌های تبدیل تاریخ را از بین می‌برد.

### robots.txt

مسیرهای محتوایی مجازند. `Disallow` فقط شامل `/administrator/`, `/cache/`, `/components/`, `/includes/`, `/libraries/`, `/modules/`, `/plugins/`, `/templates/`, `/tmp/`, `/tags/`, `/print/` است. مسیر `/tc/fairs/` محدود نشده.

### دقت تاریخ متغیر است

سه حالت واقعی در داده دیده شد:

| حالت | نمونه | رفتار ما |
|---|---|---|
| روز کامل در لیست | `09 شهریور 1405` / `31 August 2026` | `startDate` ثبت می‌شود |
| بازهٔ کامل در صفحهٔ جزئیات | microdata با `startDate` و `endDate` | هر دو ثبت، `CONFIRMED` |
| **فقط ماه، بدون روز** | `مرداد 1405` / `July 2026` | **روز حدس زده نمی‌شود** → `UNKNOWN` + هشدار |

حالت سوم واقعی است و در رویداد `53064` دیده شد. Parser عمداً روز را نمی‌سازد؛ نمونهٔ خام آن در `test/fixtures/eventro-month-only-date.html` نگه داشته شده.

نکتهٔ مهم دیگر: **صفحهٔ لیست تاریخ پایان ندارد** و فیلد `مکان` آن **شهر** است نه محل برگزاری. هر دو فقط در صفحهٔ جزئیات وجود دارند، پس fetch جزئیات اجباری است.

### منبع بالادست

صفحهٔ جزئیات فیلد `منبع ذکر رویداد` دارد. برای رویدادهای ایرانی معمولاً به `https://calendar.iranfair.com/` اشاره می‌کند — یعنی همان منبع رسمی که مستقیم در دسترس نیست. این مقدار در `raw_payload.upstreamUrl` نگه داشته می‌شود، چون نشان می‌دهد داده صرفاً ادعای یک تجمیع‌کننده نیست.

### هشدارها

- دادهٔ بین‌المللی **کهنه است** — رکوردهای آلمان مربوط به ۲۰۲۴ و «برگزار شده»‌اند. برای فاز ۳ منبع مکمل لازم است.
- پلتفرم Joomla است؛ کلاس‌های CSS ممکن است با به‌روزرسانی قالب تغییر کنند. پارسر باید **بر پایهٔ برچسب‌های متنی فارسی** (`کد رویداد:`، `تاریخ برگزاری:`، `مکان:`) بنویسیم، نه selectorهای شکننده.

## ۳. Exhibition Makers — تکمیلی

- `robots.txt`: `User-agent: * / Allow: /` — کاملاً مجاز
- پوشش بین‌المللی گسترده دارد (آلمان، ایتالیا، ترکیه، عربستان، پاکستان، عمان، چین، روسیه، امارات)
- **اما** صفحات `/en/country/{c}/` و `/en/city/{c}/` عملاً صفحات ناوبری‌اند و **هیچ تاریخ ساختاریافته‌ای ندارند** (تست شد: صفر خط تاریخ‌دار در آلمان و ترکیه)
- داده احتمالاً در صفحات جزئیات تک‌نمایشگاه است → نیاز به پیمایش sitemap

Sitemapها با الگوی غیرمعمول `?sitemapindex.xml` منتشر می‌شوند.

**نقش:** غنی‌سازی (وب‌سایت رسمی، لوگو، توضیحات) نه منبع تاریخ.

## ۴. Kabir Karsan — تکمیلی، اعتماد پایین

- وردپرس با **REST API فعال**: `https://kabirkarsan.com/wp-json/wp/v2/`
- Custom Post Type به نام `exhibitions` وجود دارد → `/wp-json/wp/v2/exhibitions`
- `X-WP-Total: 90` رکورد، `X-WP-TotalPages: 45`
- `robots.txt` محتوا را مجاز کرده، sitemap دارد

**اما کیفیت داده ضعیف است:**

- رکوردها **مقالهٔ سئویی** هستند، نه رکورد تاریخ‌دار
- فیلد `meta` برابر `null` است — فیلدهای JetEngine از REST API بیرون داده نمی‌شوند
- تاکسونومی `category-exhibition` در نمونه‌ها خالی بود
- جدول تقویم واقعی در `/exhibition-calendar/` با **AJAX** بارگذاری می‌شود و در HTML اولیه نیست

**نقش:** غنی‌سازی توضیحات با `confidence` پایین. **هرگز به‌عنوان مرجع تاریخ استفاده نشود.**

مزیت جانبی: چون REST API است، مؤدبانه‌ترین منبع برای fetch است (بدون scraping).

## ۷. قواعد اخلاق fetch (بند ۴۷)

برای **هر** منبع اجباری است:

- **Rate limit:** حداکثر ۱ درخواست بر ثانیه به ازای هر میزبان
- **Backoff نمایی** با jitter در برابر ۵xx و ۴۲۹
- **Timeout:** ۳۰ ثانیه اتصال، ۶۰ ثانیه کل
- **کش شرطی:** ارسال `If-None-Match` / `If-Modified-Since`؛ احترام به ۳۰۴
- **User-Agent شناسا** با آدرس تماس
- **احترام به robots.txt** — قبل از افزودن هر منبع جدید بررسی شود
- **دورهٔ پیش‌فرض sync:** هر ۱۲ ساعت

```
User-Agent: ExhibitionReminderBot/1.0 (+https://<domain>/bot)
```

## ۸. افزودن منبع جدید — چک‌لیست

1. `robots.txt` و شرایط استفاده بررسی شود
2. اگر API رسمی دارد، **API بر scraping ترجیح داده شود**
3. آیا شناسهٔ خارجی پایدار می‌دهد؟ (برای Dedup حیاتی است)
4. آیا تاریخ میلادی می‌دهد یا فقط شمسی؟
5. یک نمونهٔ HTML/JSON در `backend/test/fixtures/` ذخیره شود
6. Adapter نوشته شود + تست در برابر همان fixture (**نه شبکهٔ زنده**)
7. رکورد منبع با `confidence` مناسب در جدول `sources` ثبت شود
8. این سند به‌روز شود
